# 00 系统总览与架构 `[状态: 设计已批准]`

## 核心定位

面向高校医学/康复方向生物力学教学的 Web 端 3D 交互演示系统。解决教学缺乏直观强化工具的痛点：学生通过浏览器即可对人体模型做 3D 交互、查看受力场景的力学参数时序、并按部位学习知识点讲解。

## 设计目标

1. **零门槛访问**：任意主流浏览器（Chrome/Safari/Edge/Firefox）直接访问 URL，无需安装客户端、无本地环境依赖。
2. **全设备自适应**：手机/平板/桌面响应式布局，低端设备可自动降质。
3. **教学有效**：时间轴驱动的「3D 姿态 ↔ 参数曲线 ↔ 知识卡」三联动回放。
4. **零后端运行**：运行期纯静态资源，部署到任意静态托管即可。

## 技术选型

| 层 | 技术 | 理由 |
|---|---|---|
| 3D 渲染 | Three.js + glTF（Draco 压缩） | 浏览器原生 WebGL，生态成熟 |
| UI 框架 | React 18 + Vite | 组件化面板 + 快速构建，纯静态输出（实际实现采用脚手架 React 19） |
| 图表 | ECharts | 曲线缩放/联动能力（dataZoom） |
| 状态 | Zustand | 轻量全局状态（时间轴 t、选中部位） |
| 离线流水线 | Python + MuJoCo | 与 MS-Human-700 原生格式对接 |
| 部署 | GitHub Pages / Vercel / 校内静态服务器 | 纯静态文件，HTTPS + CDN |

## 分层架构

```
外部用户（教师/学生，任意浏览器）
        │ 访问
浏览器端 SPA（React + Vite 纯静态）
  ├─ 01 3D 渲染引擎（Three.js + glTF）★核心
  ├─ 02 回放与交互控制（时间轴/视角/部位选择）
  ├─ 03 参数可视化（ECharts 曲线联动）
  └─ 04 知识点标注讲解（部位关联知识卡）
        │ 按需加载（主数据流）
静态资源层（CDN / 任意静态托管）
  ├─ glTF 人体模型（骨骼层级 + 肌肉附着）
  ├─ 场景数据 JSON（关节角/激活/力矩时序）
  └─ 知识库 JSON（结构化讲解内容）
        ▲ 构建产物
离线构建流水线（Python，开发期一次性运行）
  ├─ 05 模型转换器（MuJoCo XML + STL → glTF）
  └─ 06 仿真预计算（关节力矩/肌肉激活时序）
```

## 核心流程说明（系统级）

1. **开发期**：`05 模型转换器` 将 MS-Human-700 的 XML+STL 转为 `human.glb` + `rig-meta.json`；`06 仿真预计算` 对 5 个教学场景跑 MuJoCo 仿真，产出 `scenes/*.json`；`07 知识库` 产出 `content/knowledge/*.json`。三类产物全部进静态资源层。
2. **运行期**：浏览器加载 SPA 骨架 → 按场景懒加载 glTF + 场景 JSON → 时间轴 t 同时驱动 3D 姿态、曲线游标、知识卡；用户反向拖动（曲线点击/部位点击）同样跳转时间轴。

## 关键依赖

- 外部资源：MS-Human-700（https://github.com/LNSGroup/MS-Human-700），保留出处声明与引用（ICRA 2024）。
- 前端：three、@react-three/fiber（可选）、echarts、zustand、vite。
- 流水线：python 3.10+、mujoco、numpy、trimesh、draco 编码器。

## 边界范围

- **包含**：3D 交互、参数可视化、5 个预计算受力场景、知识卡讲解、静态部署。
- **不包含**（明确排除）：浏览器内实时物理仿真（mujoco-wasm 属后续迭代）、用户账号体系、教师端场景编排器、多人在教（均列入迭代路径）。
- **数据边界**：每场景仅导出教学重点肌肉（6~10 块）数据，非全部 700 块。

## 迭代路径（后续可扩展）

1. 混合仿真：mujoco-wasm 实时参数调节（重力/外力）
2. 教师端：场景编排器 + 学生测验
3. 数据补充：Z-Anatomy 软组织模型、表面肌电数据对比
4. 多人教学：教师投屏控制、学生扫码跟随
