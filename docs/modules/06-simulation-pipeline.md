# 06 仿真预计算流水线 `[状态: 设计已批准]`

## 核心定位

开发期运行的离线仿真工具：对每个教学受力场景跑 MuJoCo 仿真，产出前端回放所需的全部时序数据。本板块决定系统的「科学可信度」。

## 设计目标

1. 数据可信：曲线经教师/导师抽查合理，关键力学峰值与文献量级一致。
2. 体积可控：单场景 JSON < 2MB。
3. 可重复：同输入必得同输出（固定随机种子与求解器参数）。

## 实现逻辑（pipeline/simulate_scene.py）

- **输入**：场景定义文件（YAML/JSON）：初始姿态、外力/载荷曲线、仿真时长、步长、目标肌肉清单。
- **仿真**：MuJoCo 逐步推进，每步记录：
  - 全部关节角度（rad / deg）
  - 关节力矩（N·m）
  - 地面反作用力 GRF（N）
  - 教学重点肌肉激活度（%MVC，每场景 6~10 块）
- **导出**：按 30~60Hz 重采样，float32 存储 → `scenes/<scene>.json`。
- **关键帧标注**：损伤风险时刻（如跳跃着陆的 ACL 峰值）由场景文件人工标注 `keyframes: [{t, label, cardId}]`，供 02 时间轴标记与 04 自动弹卡。
- **首批 5 个场景**：步态周期（Locomotion 变体）、跳跃着陆、弯腰提重物、肩关节外展、踝内翻落地（均 Full Body / Locomotion）。

## 关键依赖

- 上游：MS-Human-700 原版 XML（直接用于仿真，不经 05 的 Web 瘦身版）。
- Python 库：mujoco、numpy。
- 下游：02（回放数据源）、03（曲线数据源）、04（keyframes.cardId）。

## 边界范围

- **包含**：场景定义、MuJoCo 仿真、数据导出、关键帧人工标注、重采样与精度控制。
- **不包含**：模型转换（05）、浏览器内实时仿真（明确排除，属迭代路径）、数据的视觉呈现（03）。

## 核心流程说明

```
场景定义文件（姿态/载荷/时长/肌肉清单/keyframes）
  → 加载 MS-Human-700.xml 进 MuJoCo
  → 逐步仿真，记录 角度/力矩/GRF/激活度
  → 30~60Hz 重采样 + float32
  → scenes/<scene>.json（含 keyframes）
  → 人工抽查曲线合理性 → 进静态资源层
```

## 验收要点（P2）

- 5 个场景 JSON 齐备，单场景 < 2MB。
- 曲线经医学方向教师抽查；关键峰值与文献量级一致。
- 固定输入重跑两次输出逐字节一致（可重复性校验）。
