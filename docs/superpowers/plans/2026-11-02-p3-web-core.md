# P3 实施计划：Web 核心开发（板块 01–04）

日期：2026-11-02 ｜ 分支：master ｜ 执行方式：subagent-driven development

## 目标

把 P1（human.glb + rig-meta.json）与 P2（5 个场景 JSON）的产物变成可交互的 Web 应用：
时间轴 t 单一驱动源的「3D 姿态 ↔ 参数曲线 ↔ 知识卡」三联动回放。纯静态构建（Vite），
对应 docs/modules/01–04 四个板块，验收 = 三联动响应 < 50ms、部位点击返回正确中英文名、
build 产物可部署。

## 已核实的环境与数据契约（勘察实测，实现者必须遵守）

- **Node 便携版**：`C:\Users\Lenovo\.local\lib\node-v22.23.4-win-x64`（node v22.23.4 / npm 10.9.9）。
  Shell 无状态，每条命令前注入：`$env:Path = "C:\Users\Lenovo\.local\lib\node-v22.23.4-win-x64;$env:Path";`
- PowerShell 5.1 不支持 `&&`，用 `;`；Shell 工具 cwd 参数设仓库根 `d:\清华人体模型`。
- **human.glb 未做 Draco 压缩**（P1 决定 Draco 延后 P5，9.58MB）。DRACOLoader 只留接口不启用。
- `pipeline/out/fullbody/rig-meta.json`：`{parts:[80]}`，每项
  `{id, parent, names:{en,zh}, group:'skeleton'|'muscle'|'skin', joints:[{name,type:'hinge'|'slide',axis:[3],range:[2]}]}`。
  glTF 节点名 = body id（P1 转换契约）。
- 场景 JSON（`pipeline/out/scenes/*.json`，5 个）：
  `{scene, xml, fps:50, duration, frames, joints:[36 个关节名（= qpos 列序）], muscles:[6~8 块],
    series:{time[], qpos[][36], qfrc_actuator[][36], muscle_act[][m](%MVC), grf[][3](fx,fy,fz)},
    keyframes:[{t,label,cardId}]}`
  - grf 行是 3 分量（无时间列），时间用 series.time；
  - muscle_act 已是 %MVC（0~100）；
  - qpos 单位：hinge=rad、slide=m（MuJoCo 原生）。
- 已知模型事实：`pelvis` 带 quat 绕 x 转 90°（模型整体躺姿→站立是建模约定），
  glb 节点继承了该 quat，不要"纠正"它；`pelvis_ty` 是上下平移轴；关节角度符号
  knee 正=屈曲、subtalar 正=内翻、L5_S1_FE 负=前屈。
- 知识内容（07 板块）P4 才生产：P3 用 stub（`content/knowledge/*.json`，每场景 2 张
  keyframe 卡 + 4~6 张部位卡），字段契约按 04 文档，正式内容后续替换 JSON 即可。

## 架构决策

- 目录 `web/`（仓库根下）；Vite + React 18 + **TypeScript**；测试 Vitest；库 three / echarts / zustand。
- 状态：`src/store.ts` Zustand `{sceneId, t, playing, playbackRate, selectedPartId, scene, rigMeta, knowledge}` +
  actions。t 为唯一驱动源；所有联动由 t 派生（02 文档）。
- 静态资产同步：`web/scripts/sync-assets.mjs` 把
  `pipeline/out/fullbody/{human.glb,rig-meta.json}`、`pipeline/out/scenes/*.json`、
  `content/knowledge/*.json` 复制到 `web/public/data/`（可再生产物 → gitignore）。
- 三联动分发全部发生在 t 变更的同一个调用栈内（RAF 帧内同步）→ 天然 < 50ms。
- 姿态驱动正确性用 **MuJoCo FK 对账 fixture** 锁定（T3）：python 脚本对若干采样帧导出
  各 body 世界位姿真值，vitest 用 three 复算对比 < 1e-3。

## Task 3：3D 渲染引擎（01）+ FK 对账（核心风险任务）

**Files**：`web/src/three/poseMap.ts`、`web/src/three/SceneManager.ts`、
`web/src/components/Viewport.tsx`、`pipeline/tools/fk_reference.py`、
`web/src/tests/poseMap.test.ts`、`web/public/data/fk-reference.json`（fixture，gitignore 或入库均可）

- Step 1：`pipeline/tools/fk_reference.py`（.venv 运行）：加载 MS-Human-700.xml，对
  gait_cycle.json 的 3 个采样帧（0、mid、peak knee）的 qpos 做 `mj_forward`，导出
  `{frame, qpos, bodies:{<bodyId>:{pos:[3], quat:[4]}}}`（取 6~8 个代表性 body：
  pelvis/thigh_r/shank_r/foot_r/torso/clavicle_r/upperarm_r/hand_r 等，以 rig-meta 实际 id 为准）
- Step 2（先写测试）：`poseMap.ts`：
  - `applyPose(root: Object3D, joints: {name,type,axis,range}[], q: Record<jointId,number>)`：
    对每个 joint：hinge → `node.quaternion = q0 ⊗ quatFromAxisAngle(axis, angle)`；
    slide → `node.position = p0 + axis·q`（q0/p0 为加载时缓存的初始局部位姿）；
    越界按 range clamp。**层级自动传递，无需逐级累乘。**
  - FK 对账测试：加载 glb（vitest 里用 GLTFLoader 的 parse + polyfill 或改为对
    「手工构建的最小层级」测试 + 浏览器实测兜底——若 vitest 加载 glb 复杂，
    允许降级为：fixture 驱动的纯数学对账（用 three 的 Object3D 树手工按 rig-meta
    parent/pos/quat 重建节点），断言与 MuJoCo FK 差 < 1e-3 m / < 1e-3 rad）
- Step 3：`SceneManager.ts`：GLTFLoader 加载 `/data/models/human.glb`（进度回调）；
  OrbitControls（触屏/鼠标）；Raycaster 拾取 → `onSelectPart(partId)`（命中 mesh 向上找到
  具名 body 节点）；高亮 = 命中部位材质 emissive + 其余半透明（可恢复）；
  `setLayerVisible(group, visible)` 与 `setLayerOpacity(group, v)`（按 rig-meta group 分组）；
  `setPose(q)` 每帧由 02 调用；`focusPart(partId)`（相机特写，04 反向定位用）
- Step 4：`Viewport.tsx`：React 封装（加载进度条、失败重试按钮、resize 自适应、清理函数）
- Step 5：browser 代理实测：dev server 起服务 → 截图验证站立 T-pose/0 帧正常、
  点击大腿高亮且返回中英文名、拖拽旋转可用 → 修问题
- Step 6：build + 全量测试 → commit `feat(P3): 3D 渲染引擎与 MuJoCo FK 对账`

## 风险与预案

| 风险 | 预案 |
|---|---|
| glb 节点名与 rig-meta id 不一致（P1 转换细节） | T3 第一步先 script 实测 glb node 名单，对不上则查 P1 转换代码修映射 |
| MuJoCo→three 姿态方向/手性错位 | FK 对账 fixture 是唯一真值；不通过就修 poseMap，禁止目测调参 |
| vitest 加载 glb 复杂 | 允许降级为手工节点树 + 纯数学对账，浏览器实测兜底 |
| npm 网络慢 | 使用默认 registry；如超时重试一次 |
| ECharts 游标频繁 setOption 卡顿 | 游标走 graphic/markLine 增量更新，数据曲线只建一次 |
